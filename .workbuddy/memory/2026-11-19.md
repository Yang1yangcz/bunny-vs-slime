## 新交付：duel-live.html（可实时演算的单文件对战页）

用户不再需要视频，改为要一个双击就能跑、实时演算的对战 HTML。**这是全新一版，不复用视频管线。**

### 文件
- `bounce-duel/duel-live.html` — 交付物，480KB，图片全部 base64 内联，可单独拷走运行
- `bounce-duel/live.template.html` — 带 `__IMG_*__` 占位符的源模板（改这个）
- `bounce-duel/_build_live.py` — 内联图片生成 duel-live.html
- `bounce-duel/_test_live.py` — 无头 Edge + CDP 跑 N 局统计胜率并截图（依赖技能里的 record.py 的 CDP 类）

### 数值设定
- 兔子：HP 10000、ATK 3000；锤击 = 70%×ATK + 1%×当前生命（满血 2200）
- 兔子大招：HP < 20% 触发，先锁血 3s + 冰岛冲击（占位 2900 空中伤害 + 1.5s 眩晕，每局一次）
  - 关键实现：**伤害结算时把这一下截停在 20% 线**，避免「28% 直接被一发打到 10%」才触发
- 史莱姆：HP/ATK 对称 10000/3000（用户没给，我定的），单球 60%×ATK=1800，命中吸血 3%（300）
- 技能1 站在道德制高点：CD 18s，浮空 5s，免疫 `kind:'ground'` 伤害（锤子是 ground，冰岛冲击是 air）
- 技能2 历史的回眸：CD 26s，回「前一个 10s 窗口承伤」的 30%，把「本 10s 窗口承伤」的 20% 打回去，然后停手 10s
  - 「10 秒前受到的伤害」我按 **上一个 10 秒窗口** 实现（否则只有一个时间点，取不到数）

### 平衡实测（无头跑，每档 8 局）
- 冰岛冲击占位 2200 → 兔子 0:6；2700 → 4:4 与 2:6；2900 → 3:5；3200 → 6:0
- 当前 2900，兔子约 40%。**空大伤害是唯一有效的平衡旋钮**，等用户给出真实设定再调

### 踩过的坑
- 延迟伤害原本用 `setTimeout`，快进测试时不会触发，导致测出的胜率虚高 → 改成按模拟时间调度的 `pending` 队列 + 局数代号 `gen` 丢弃上一局事件
- 画布比例：为了填满竖向空间把 arena 从 960×600 改成 960×720，舞台宽高用 JS 按比例算，别用 CSS aspect-ratio（会拉伸）
- 详细模式用底部抽屉 + 打开时给画布留 `reserve` 高度，否则抽屉压住半个画布

### 调试接口
`window.__sim.advance(秒)` 快进、`window.__sim.state()` 取状态。留着方便以后验证。

## v2.5：冰岛冲击 3 次 + 回血 + 伤害统一百分比（git tag v2.5，提交 72e7b53）

### 机制
- 大招从「一局一次」改为 `ult.uses: 3`：每掉到 20% 血触发一次；`ultLeft` 计数，用尽后不再锁血、可被击杀
- 释放回血 = `ult.healRatio 0.30` × 此前累计 `rabbit.dealt`。因为有锁血线，三次必定全部触发
- 伤害公式全部改成 `atkDmg(who, ratio) = who.atk × ratio`：
  锤击 0.70(2100)、大招 1.00(3000)、单球 0.85(2550)、吸血 0.10(300)
  → 因为 atk 3000 / hp 10000，系数 × 0.30 就是「对方基础生命的百分比」

### 关键平衡结论（用 _tune.py 无头跑）
- 史莱姆 10000 血：兔子 8:0（大招 3 次共 9000 = 90% 血，史莱姆必死）
- 14000 血 + 周期 2.6：史莱姆 16:8
- **12500 血 + 周期 2.6 + 单球 0.85：56 局 28:28，平均 27.5s** ← 采用
- 教训：8~12 局的样本完全不可信（同一参数能出 6:6 和 4:8），要 24 局以上

### 两个真 bug
1. **锁血线被同帧打穿**：`damage()` 里 `if (hp > floor && hp-amount < floor)` 只挡「跨线」那一下；
   hp 正好等于 floor 时同帧第二段伤害直接归零 → 出现「7.5 秒被秒、大招 0 次」。
   改成「已压线则本帧完全免伤」
2. **reset() 不重读 CFG**：`f.hp = f.maxHp` 用的是建对象时缓存的 maxHp，
   改 `__CFG.slime.maxHp` 后点重新开局无效（我因此有一轮测试白做）。改成每次重开读 `f.cfg.maxHp/atk`

### 测试方法论（重要）
- 页面自带 rAF 主循环会和 `__sim.advance()` 叠加 → 结果不可复现。加了 `__sim.pause()/resume()`
- 即使暂停，`Math.random` 序列仍无法完全复现（两次同种子结果不同），所以**只能靠大样本**
- 无头截图在 pause 模式下 canvas 会整片空白（合成器不重绘），是截图伪影，不是渲染 bug；
  要截画面就别 pause

### 视觉
- 横幅改胶囊样式（深色底 + 蓝描边），原来白字会被角色和极光背景吞掉
- 回血用 `heal()` 自带的绿色 +N，另加三重绿环 + 三音上行音效

## v2.7：吸血改为按实际伤害结算 + 史莱姆血量 13500（git tag v2.7，提交 7863a6a）

- 吸血：`lifestealAtk 0.10`（固定 300）→ `lifestealRatio 0.10` + `Math.ceil(dealt * 0.10)`
  - 单球 2550 → 每次回 255；`damage()` 返回真实伤害，被免疫/锁血时 dealt=0 不回血
  - 注意 `heal()` 会被 maxHp 截断，满血时回血为 0，所以「累计回血 / 命中次数」不等于单次量
- 史莱姆 maxHp 12500 → **13500**（比兔子高 35%）；atk 保持 3000 不动
  - 理由：所有伤害都是 atk×百分比，改 atk 只是把双方所有招式等比缩放，对胜负影响很小
- 实测（每档 24 局）：13000 → 兔子 17:7(71%)；**13500 → 11:13 + 16:8 + 14:10 = 41:31(57%)**；
  14000 → 18:30(37.5%，48 局)。最终 13500，72 局 57%，平均 28.4s
- 敏感度极高：±500 血就能让胜率跳 20 个点，必须 24 局以上才测得准
